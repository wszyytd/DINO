# 扩采参考引导匹配照片

目前模型在训练的两辆车上能拟合，CLS基线也排对全部10组，尚未证明对新车、新参考有效。本次扩采增加参考变化和独立验证，不以继续降低旧训练集loss为目标。

## 本次计划

`collect_match_photos.py`从服务器实际CARLA资产中选择6–8个有颜色属性的四轮车型。验证、测试各留2个，其余用于训练，三个划分不共享车型。默认排除ID中明确包含警车、救护车等标记的资产，但不能仅凭名称保证其余都是普通轿车。实际资产包括出租车或商用车时，必须在照片中核查涂装和结构，区分容易负例与相似车辆难例。

程序从当前地图出生点选择9个位置，三个划分各用3个。从每个出生点分别开始尝试最远点选择，保留找到的最小间距最大的方案。默认自动选点，采集间距下限为40米；不再强制较小地图满足9点两两80米。这里的40米是采集配置，不代表背景独立，航拍范围仍可能重叠。每组两辆车用相同配置颜色，交换槽位并改变朝向，在正午和低太阳高度条件下拍摄。每组两辆车分别作为参考，均重新拍参考图，不复用旧的唯一白车参考。

终端计划和成功采集保存的 `collection.json` 中，`anchor_selection` 记录实际最小间距、9个选中出生点及其位姿。该算法是多起点贪心搜索，不声称找到数学上的全局最优。如果明确传入 `--min-anchor-distance 80` 等数值，程序严格执行该下限，不自动放宽；选点失败会报告找到的最好间距及出生点数量。

查询相机的方位以场景出生点朝向为基准，与哪辆车是真目标无关。只交换参考身份时，不让查询相机跟着目标车转向，避免把真值目标的信息写进取景方式。参考图仍围绕其对应车辆拍摄。

以下是8车型时的计划：

| 划分 | 车型资产 | 位置 | 参考采集场景 | 查询裁剪 | 参考裁剪 |
|---|---:|---:|---:|---:|---:|
| train | 4 | 3 | 24 | 480 | 24 |
| val | 2 | 3 | 12 | 240 | 12 |
| test | 2 | 3 | 12 | 240 | 12 |
| 合计 | 8 | 9 | 48 | 960 | 48 |

原始相机2048×1536，每个场景10个共享查询视点。包括高空、下降、侧面、前后斜侧、另一侧及较高斜视。1008是计划导出的车辆裁剪数，不是独立场景数量，也不保证每张图都能辨认身份。

服务器只有7种资产时，使用3种训练、2种验证、2种测试；3种训练车轮流两两配对，计划1200张查询加60张参考，共1260张。只有6种时，各划分2种，计划共756张。终端会打印根据实际资产生成的数量，不要求补造第8种车型。

这些是同一地图内未见车型资产、未见位置的检查，不是跨地图或现实泛化。车辆实例编号A/B只在各次场景中有意义；正负标签表示候选是否与该次参考属于同一实例。

## 服务器采集命令

先保持CARLA仿真器运行。在另一个终端执行以下命令。采集用`carla10`，不是训练用的`dino-probe`。

```bash
cd /mnt/fast18/sunbo/DINO
git pull --ff-only origin main
conda activate carla10

# 只读服务器资产和地图，打印实际可采计划，不拍照、不建立输出目录
python collect_match_photos.py --dry-run

# 实际采集，输出目录自动按时间命名，保留旧数据
python -u collect_match_photos.py
```

需要空的受控场景。不会删除其他车辆或切换地图。若已有同步tick主控，先停止该客户端再决定是否明确使用`--take-tick-ownership`。少于6种车型、找不到9个满足间距的位置，或连接失败时会在拍照前停止，不替换成不存在的资产。

若车辆无法生成、静止检查失败、截图无效或清理失败，采集立即停止，保留已拍图片和`collection.json`错误记录。不要直接删除或覆盖失败目录。排查后可使用下面的续采模式，或者使用新的运行目录。

## 中断后续采与小规模试验

`--resume` 读取原计划，校验已完成场景的配置、地图、参考身份、视图数量和图片，只拍缺少的场景。未完成场景如需重拍，会先原样移到同一采集目录的 `_failed/` 下；不会覆盖成功图片。续采前仍需健康、空闲的 CARLA，使用原地图、出生点布局和车型。上次清理车辆或恢复设置失败时，先重启 CARLA，再开始续采。

`--pilot` 进一步缩小计划：保留所有已完成场景及其A/B参考配对，缺少的划分只补第一组A/B参考。原60场景计划保存在 `original_plan`，本次标为 `scope: reduced_pilot`；不会把第27个半成品改成成功。

2026年10月28日这次数据完成了26个训练场景、520张查询和26张参考。小规模方案再补2个验证场景、2个测试场景，共84张裁剪图，总计630张。验证与测试各仅一个位置、一个光照条件；用于流程和初步泛化检查，不能代表完整计划的覆盖程度。

先做离线只读检查，无需连接CARLA，也不修改数据：

```bash
python collect_match_photos.py --resume data/more_photos_20261028_030040_745590 --pilot --dry-run
```

实际续采使用后台任务，终端断开后采集客户端继续运行；CARLA服务本身也必须保持运行。日志追加保存：

```bash
nohup python -u collect_match_photos.py --resume data/more_photos_20261028_030040_745590 --pilot >> out/more_photos_pilot_20261028.log 2>&1 < /dev/null &
tail -f out/more_photos_pilot_20261028.log
```

查看日志时按Ctrl+C只会退出 `tail`。若再次失败，先检查日志和CARLA状态，再运行相同续采命令，会重新校验并跳过已经完成的场景。无需缩小计划时去掉 `--pilot`；已经缩小的计划不会自动恢复到60场景。

若训练和验证已完成，但测试组在 `cannot spawn` 处失败，且测试的A/B两组都尚未成功，可加 `--retry-test-placement`。程序先在原先保留给测试集的备用位置实际试放两辆车，依次尝试原间距、12米、16米；试放车辆清理并推进一帧后才进行下一次试放或正式拍摄。任何清理失败或CARLA接口异常都会停止，不把它当成位置不合适而继续重试。

成功的摆放同时应用于测试A/B两组，写入 `placement_revisions`；训练、验证照片保留不动，生成失败的旧尝试仍归档。若任意一组测试参考已成功，程序拒绝更换摆放，防止两组测试几何不一致。预检仅检查生成和清理，不证明后续所有视图无遮挡、车辆静止或裁剪有效，拍照时仍执行原有检查。

```bash
nohup python -u collect_match_photos.py --resume data/more_photos_20261028_030040_745590 --pilot --retry-test-placement >> out/more_photos_pilot_20261028.log 2>&1 < /dev/null &
```

2026年10月29日检查同步原图：82号位置、12米间距能放下两车，参考与高空图正常；下降图已出现建筑内部结构，侧视原图均值约0.206、99.87%像素接近黑色。相机的水平偏移约23米，进入了路旁建筑范围。失败场景整体保留，不参与配对清单。

这一小试验可保留已确认的82号位置和12米间距，用 `--test-camera-radius 10` 将尚未成功的测试查询相机水平偏移限制在道路中心10米内。通过增加俯视角实现，方位与拍摄距离保持原值，低角度参考图也保持原值。测试视点改名为 `_raised` 并保存实际仰俯角，计划标注 `test_view_scope`，旧视点和新视点保存于 `camera_revisions`。这轮主要评估低角度参考到高俯视候选的匹配，不代表原计划的低角度测试成绩。

此选项与 `--retry-test-placement` 分开使用，避免再次更换已确认的车辆位置。只修改两组未完成的测试查询视点；只要任意一组测试已成功，就拒绝调整。像素质量、车辆静止及完整裁剪检查继续执行。10米约束依据本次82号位置的道路范围，不是其他地图的通用无遮挡保证。

```bash
nohup python -u collect_match_photos.py --resume data/more_photos_20261028_030040_745590 --pilot --test-camera-radius 10 >> out/more_photos_camera_retry_20261029.log 2>&1 < /dev/null &
```

## 采完先看什么

实际输出位置会在终端打印，例如`data/more_photos_日期时间`。检查：

- `collection.json`必须为complete，实际完成场景数与其中计划一致。
- `index.html`可逐组查看真实图片。各车型实际颜色和涂装需看图核实。
- 留意遮挡、两车重叠、图像过小、参考是否清楚。真值包围盒只给位置，不证明可见或可辨认。
- `pairs_train.json`、`pairs_val.json`、`pairs_test.json`只在全部采集成功并通过跨划分图片检查后输出。

现有高空或远景即使标签正确，也可能没有足够辨识信息。不能把标签存在当作每张图片都必须有高置信度的依据。
