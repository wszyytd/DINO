# 全状态更新与真实观察价值诊断

承接 [固定 16 状态更新对照](evidence-update-comparison.md)，本轮使用全部去重的价值训练状态，不再按收益范围筛选。正式训练入口、动作选择策略和冻结表征权重保持原样；新增入口 `run_evidence_observation_diagnostics.py` 运行隔离对照。

## 已完成结果（2026-11-04）

首轮 seed 7 的 8 组实验已完成：两个表征分支 × 四条件，每组 2000 次更新。训练和旧开发位置各 96 条记录、去重后各 87 状态，每个角色对应 8 个任务、4 个成对参考的拍摄配置，不能把这些历史组合当成 87 个独立场景。

下表是开发集动作平均 regret，即最佳真实后续动作的 margin 增量减去所选动作的增量，越低越好。两个分支的匹配器不同，标签也不同，应在各列内部比较，不能据此直接评判哪种表征更好。

| 方法 | alpha=0 | alpha=0.1 |
|---|---:|---:|
| 随机动作的期望 | 0.291026 | 0.063047 |
| 原逐状态更新 | 0.339740 | 0.046834 |
| 全状态共同更新 | 0.286966 | 0.071364 |
| 同结构、零观察输入 | 0.231801 | 0.053639 |
| 同结构、真实后续特征 | 0.155058 | 0.097036 |

真实观察相对零输入控制在 alpha=0 下降 33.1%，在 alpha=0.1 上升 80.9%。前者四个开发拍摄配置都改善，后者四个都变差；但配置少且相关，这些不是显著性结论。alpha=0 的总体改善约 87% 来自 pair1/light1 配置，收益分布不均匀。alpha=0.1 的较大损失也主要在该配置中（real 0.310108、zero 0.176736、random 0.214965）。

训练拟合与开发效果并不一致：

| 分支 | 逐状态训练加权 MSE | 共同更新 | 零观察控制 | 真实后续特征 |
|---|---:|---:|---:|---:|
| alpha=0 | 0.190997 | 0.023782 | 0.000392 | 0.000288 |
| alpha=0.1 | 0.156651 | 0.002149 | 0.001135 | 0.000300 |

真实特征能够明显加快训练拟合，两分支的最终训练动作 regret 分别为 0.000601/0.000851。但不能把训练改善解释成跨位置泛化已经成立。共同更新也不是单调稳定：alpha=0 的末段出现误差反弹；按相同 1914 个状态处理预算比较，两个分支共同更新的训练 MSE/regret 均比逐状态差。它用更多状态计算换取了等更新数下更好的拟合，没有证明算力效率更高。

结论：全状态拟合能力已得到进一步验证，未来观察输入在一个分支有开发收益，但另一个分支失败。下一步先复现多个优化种子并检查困难配置的动作级误差，暂不直接投入概率视角预测器或宣称流形机制成立。失败可能涉及过拟合、上游表征、记忆压缩、缺失质量输入和价值代理目标；本实验没有把这些原因分离，不能武断归因。

源 checkpoint、标签和特征清单 SHA256 在运行前后相同。训练重算标签最大差异 alpha=0 为 3.099e-6，alpha=0.1 为 1.907e-6；冻结上游参数和梯度检查通过。开发记录只在最终检查点评估。全量 205 项测试通过、Ruff 通过；曲线已实际查看，逐配置结果已核对。按用户偏好由作者自行复核，没有使用子代理，也不声称独立代码审查。

## 四个条件

| 条件 | 更新方式 | 输入 | 解释 |
|---|---|---|---|
| direct_single | 每步一个状态 | 当前参考、记忆、分数、计数和动作 | 原价值结构基线 |
| direct_joint | 每步累计全部状态梯度 | 同上 | 检查稳定更新是否推广至全部训练状态 |
| observation_zero_joint | 同上 | 当前输入＋全零观察输入 | 与观察条件相同结构/参数量的控制 |
| observation_real_joint | 同上 | 当前输入＋真实后续观察 token 和有效标记 | 有未来信息的诊断，不能部署为飞行策略 |

观察头保留 ActionValue 当前状态表示，增加观察编码和残差评分。残差最后一层零初始化，因此初始输出与对应直接价值头相同；zero/real 两条件全部初始参数一致。真实特征为冻结 `encode_observations` 输出的五个有序 token，当前源实验是 5×64，而非教师预测头的 5×384。网络输入不包含真实身份、更新后匹配分数或收益标签。失败拍摄的观察输入为零且标记无效。

记录按原有 history/action 顺序重建，逐项验证当前输入和真实 margin 增量。保存的旧标签仍是训练目标，重算只用于验证。失败、负收益和近零收益动作都保留；去重不进行收益范围筛选。各条件使用相同记录，未消费任何预留测试角色。

## 优化与预算

沿用奇数步困难状态、偶数步全部状态的原采样目标。joint 使用各阶段的精确期望梯度，每状态先平均合法动作误差，整个训练集按阶段权重加权。分块仅控制内存，全局归一化不因块大小变化，累计完才裁剪/更新。

预设首轮：seed 7，两个表征分支各四条件，2000 更新，lr=1e-4，AdamW weight_decay=.01，梯度裁剪 5，chunk=32，CPU 两线程。每 50 步记录训练曲线；开发只评估最终检查点，不据此选步数。

每次 single 更新前向一个训练状态，joint 前向全部 87 状态，包含困难阶段权重为零的状态。最终分别处理 2000/174000 个状态。另以固定算式取得最大可行偶数 joint 更新 22，对比 single 更新 1914，两者均处理 1914 个状态并结束在全量阶段。状态前向数不等于 FLOPs 或耗时。

## 开发与指标

`--include-development` 显式启用源运行的 eval 角色。本轮是以前用于开发的位置 105；身份与训练重合、参考背景未独立，不是新的独立测试。训练是位置 64。角色检查拒绝位置、图片或任务重叠，并核对冻结表征的训练角色。仅为所需训练/开发角色加载特征张量。

报告训练加权 MSE、动作平均 regret、随机动作期望 regret、有效差异动作对排序、近最佳动作率。开发 MSE 对状态均匀加权，不能直接与训练困难/全量混合权重相比。保存全状态指标，以及收益范围至少 .05 的诊断子集；子集不用于选训练数据。逐状态预测、标签、动作顺序和按物理拍摄配置聚合的指标位于每个 `fit.json`。

这些是固定历史上的下一动作评分，不是闭环无人机轨迹；真实后续特征条件不是严格性能上界。它没有后续图像质量指标，也不能恢复记忆压缩中丢失的全部历史信息。只有它优于同结构零输入控制，才有更直接的证据支持继续构建未来观察预测器；单次失败也不证明未来信息无用。

## 服务器复现

在已有实验环境和已更新的工作树中执行，无需新增依赖或重算 DINO：

```bash
cd /mnt/fast18/sunbo/DINO-evidence-300fcf8
git fetch origin codex/active-evidence-pilot
git switch --detach origin/codex/active-evidence-pilot
conda activate dino-probe

python -u run_evidence_observation_diagnostics.py \
  --data ../DINO/data/more_photos_20261028_030040_745590/train \
  --cache ../DINO/out/more_photos_20261101_135207_870565/features \
  --source-run out/active_evidence_20261104_022430_404842 \
  --output out/evidence_observation_diagnostics_seed7 \
  --steps 2000 --seeds 7 --lr 0.0001 --threads 2 --chunk-size 32 \
  --include-development
```

该隔离诊断当前使用 CPU。去掉 `--include-development` 可仅检查训练拟合。三种子复现把 `--seeds 7` 改为 `--seeds 7 17 27` 并指定新的输出目录；不覆盖已有运行。三个优化种子不等于三个独立数据集。

## 本地运行

输出：`D:/Work/DINO-active-evidence/out/evidence_observation_diagnostics_20261104_01/`。

`run.json` 保存源文件/源码哈希、角色、去重索引、误差核对和各条件结果；各分支的 `records.pt` 保存固定输入，`fit.json` 保存详细指标，`updates.json` 保存逐次损失与梯度范数。`last.pt` 标为 `diagnostic_only`，正式策略加载器明确拒绝加载。异常会把运行标为 failed；旧输出被拒绝覆盖。
