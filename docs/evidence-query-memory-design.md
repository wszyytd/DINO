## 1. 先用简单话说明这次要做什么

无人机已经看过一辆车的正面。现在又看到了侧面：

- 如果侧面有可靠的新线索，记忆应能利用它。
- 如果只是重复正面，判断不应因为重复次数增加而持续漂移。
- 如果新图模糊、裁偏，已有可靠认识应尽量保留。
- 如果新证据证明以前认错了，模型必须允许纠正。

本轮研究问题是：**有限的车辆记忆，能否通过连续观察增加或保留身份辨识能力？**

不要求每一张照片都提高准确率，也不要求每个查询的得分单调上升。已经认对、没有新线索或证据互相矛盾时，这些要求并不合理。

本轮借鉴 MulMON 的“用未输入的观察检验表示”和 UpdateNet 的“学习更新规则”，把监督落实为独立查询的车辆身份判断。不复刻两篇论文的全部模型。

### 3.3 上游的真实限制

老师定位分支是本地复现及小规模拟合，不是老师原始成熟网络。现有候选区域依赖一张固定的定位参考图，并使用真实掩膜与车辆 ID 辅助分车、裁图和关联。

本轮对同一条写入路线固定 source_reference_id。更换独立查询时，不重新定位、不更换输入区域、不重新构造记忆。否则比较的就不是同一份记忆。

因此只能说：**给定相同候选观察，记忆能够接受不同查询。** 不能声称上游采集已经完全不依赖参考图。

## 4. 论文依据与迁移边界

### 4.1 MulMON

论文：Learning Object-Centric Representations of Multi-Object Scenes from Multiple Views，NeurIPS 2020。

它用物体槽位维护潜在表示，在多次观察之间迭代更新；训练中留出部分视角，利用场景表示与查询视点生成这些视角的图像。原实验面向静态场景，使用视点信息，任务包括生成和分割。

本轮借鉴“写入观察与检验观察分离”；把生成任务换成身份匹配，是本项目提出的适配，不是论文已经验证的车辆识别方法。MulMON 的潜在状态变化或不确定度，不直接等于身份辨识收益。

来源：[官方论文](https://proceedings.neurips.cc/paper_files/paper/2020/file/3d9dabe52805a1ea21864b09f3397593-Paper.pdf)、[作者公开全文](https://arxiv.org/html/2111.07117v1)。

### 4.2 UpdateNet

论文：Learning the Model Update for Siamese Trackers，ICCV 2019。

其更新器输入初始真实模板、累计模板、当前预测位置的模板；以后一帧真实区域特征监督更新结果。当前训练模板包含实际定位误差。论文使用分阶段生成训练数据，没有采用整段 BPTT。

本轮借鉴可学习更新和有误差输入的训练，保留当前短序列 BPTT。它主要优化后续跟踪模板，不保证永久保存所有历史外观；历史查询保持是本项目另加的要求。若后续引入可靠参照，必须单独报告额外存储，不能假设第一帧一定可靠。

来源：[会议论文](https://openaccess.thecvf.com/content_ICCV_2019/papers/Zhang_Learning_the_Model_Update_for_Siamese_Trackers_ICCV_2019_paper.pdf)、[作者公开全文](https://arxiv.org/html/1908.00855v1)。

## 5. 模型总体结构

    当前照片
        ↓ 既有区域提取、仿真辅助路由
    每辆车的 RGB 裁图
        ↓ 冻结 DINOv2 + view 分支 + 4×4 池化
    当前观察 X：16×256
        ↓ Writer：8 个可学习查询
    本次观察表示 W：8×256
        ↓ 与该车旧记忆进入 Updater + Gate
    新记忆 M：8×256
        ↓
    Reader + Matcher ← 独立查询 Q：64×256
        ↓
    各候选车辆得分 + Null

同一张图出现 A、B 两辆车时，各自生成观察并更新各自状态。更新器权重共享，车辆状态分开。增加车辆数量增加状态条目，不需要为每辆车训练一套网络。

第一轮没有新增共享场景记忆。长期设计中的共享搜索记忆与本轮每车身份记忆不是同一个模块，不要把它们混入本实验。

## 6. 哪些是参数，哪些是记忆

训练参数包括 Writer、Updater、Gate、Reader、Matcher 和 Null 分数。它们通过训练跨车辆学习通用规则。

推理状态只属于当前路线中的车辆：

| 状态 | 形状 | 含义 |
| --- | --- | --- |
| slots | B×K×8×256 | 每车当前记忆内容 |
| seen | B×K | 是否实际建立过状态 |
| count | B×K | 实际写入次数 |

B 是批次，K 是候选容量，不是 Writer 的槽位数。不同路线开始时清空状态；路线中车辆暂时不出现时保留原状态。

float32 下单车 slots 为 8192 字节，不含网络参数、训练计算图和临时张量。训练时反向传播占用的显存不等于部署记忆大小。

当前首次观察直接写入 Writer 输出；后续：

    proposal = Updater(old_memory, current_written)
    gate = sigmoid(Linear(concat(old_memory, proposal)))
    new_memory = old_memory + gate * (proposal - old_memory)

每个槽位一个标量 gate，共八个；它不是显式质量概率。CrossBlock 本身包含残差，不能把上述过程简单解释成两个独立描述向量的凸平均。

## 7. 输入输出约定

### 7.1 冻结特征

| 用途 | 编码方式 | 形状 |
| --- | --- | --- |
| 写入观察 | FrozenRuntime.independent + pool | 16×256，valid 为 16 |
| 独立查询 | FrozenRuntime.reference | 64×256，valid 为 64 |
| 网络输出 | 对 K 个候选与 Null 评分 | K+1 |

查询必须从独立源 RGB／裁图经 reference 分支重新编码。不能把现有 16×256 写入缓存改名当成 64×256 查询，也不能随意补零或复制 token。接口本身允许不同查询长度，不代表两条预处理分支语义相同。

旧写入特征只有在原图、裁框、权重、编码配置和源码来源完全一致时才可复用。新查询与受损裁图需在服务器另建缓存。

### 7.2 拟新增批次接口

新数据模块为纯 Python／NumPy，不导入 torch。新训练模块在服务器将数组转为张量。

    observation:       float32[B,T,K,16,256]
    observation_valid: bool[B,T,K,16]
    step_valid:        bool[B,T]
    query:             float32[B,T,J,64,256]
    query_valid:       bool[B,T,J,64]
    query_label:       int64[B,T,J]       # 0..K-1 或 K 表示 Null
    query_active:      bool[B,T,J]
    query_group:       int8[B,T,J]        # 0=current/general，1=history
    repeat_candidate:  int64[B,T]         # -1 表示本步不计算重复分支

ID、图像路径、方位组、裁框、质量类型、标签和老师分数均保留在元数据或监督侧，不作为外观特征传给模型。query_label 也只供损失使用。

通过 score_queries 把查询维 J 展开后调用既有 model.score，输出 B×J×(K+1)。查询为空的补齐位置必须先过滤，不向旧接口传入全无效的查询。评分不得修改状态。

## 8. 数据设计：先定义观察和查询，再生成训练序列

### 8.1 基本记录

每个观察或查询至少保存：

| 字段 | 含义 |
| --- | --- |
| sample_id、scene_id、vehicle_uid | 稳定记录编号、场景、车辆实例；UID 应跨布局可追溯 |
| split | train / validation / test；旧 probe 保留原名 |
| source_rgb、source_rgb_sha256、frame_id | 原图来源 |
| crop_box、crop_sha256 | 原图上的裁框及实际裁图内容哈希 |
| source_reference_id | 上游使用哪张固定定位参考图 |
| view_group、view_group_source | 粗外观组及其依据；无法确认则为 null |
| perturbation、parent_sample_id、seed | 扰动类型、原样本、可复现随机种子 |
| encoder_role、cache_key、cache_sha256 | 写入／查询分支及缓存校验 |
| eligible | 固定前端规则是否允许作为输入，独立于后续模型是否选择写入 |

同一个源图的不同裁剪或增强版本，仍属于同一源图组。不能将它们分别放在同一 episode 的写入和独立查询中。

### 8.2 两级划分

外层划分控制泛化：正式数据按车辆实例划分 train/validation/test，并控制布局和背景重复。相同资产实例只换场景或重命名 A/B，不自动变成独立身份。

内层划分控制一次任务：同一 split 内，为每个 episode 选择写入集合 C 和查询集合 Q。Q 的源 RGB 不得出现在整个 C 中，而不只是排除当前一步；同图另一辆车的裁剪也排除，避免共享背景和同帧线索。

不同训练 episode 可以交换某张图的写入／查询角色；这不等于跨外层划分泄漏。评估 episode 的重叠必须记录，并按车辆／场景汇总，不把共享照片的前缀当独立样本。

旧 probe 不能用于选轮次、调阈值、挑种子。当前小数据采用预先固定配置；需要调参时另建明确的训练内校准划分，不能悄悄使用 probe。

### 8.3 路线和查询的关系

第一版从现有图连续路线截取 4 或 8 步窗口；查询从同一外层划分、同车、窗口外的独立原图中选。固定评估还应包含较长窗口，以观察遗忘。

不删除路线中间帧来绕开查询冲突；选不到独立查询就记录原因并剔除该 episode。允许车辆缺席、只更新另一辆车、重复遇到同一记录。训练机制诊断可以依据可见性构造指定情形，但必须标记为受控采样，不能拿它评价主动飞行效率。

### 8.4 怎样划分当前外观与历史外观

view_group 是粗采样标签，不是记忆槽位的固定含义。可由可靠的仿真相对观察方位或人工标注产生；它只参与采样和分组评价，不输入网络。

不能把相机 yaw 直接当成相对车辆方位；必须考虑相机位置和车身方向。元数据不足时标记 null，不编造车头、车尾标签。

有组标签时：

- 当前组查询：与本次写入车辆当前外观组相同，但源图独立。
- 历史组查询：该车辆此前见过的其他外观组，查询图仍未写入。
- 若当前组以前没出现过，额外标记 candidate_complementary=true；它只是潜在互补，不保证有身份收益。

无组标签时允许 query_all 模式：随机独立查询用于流程验证，但关闭基于方位的 history 分组，不能宣称测到了某个具体视角的知识保持。

query_all 下 C 与 D 的历史监督差异不存在，因此不得把它们作为有效的历史保持消融；该模式只完成工程检查和通用查询基线。

第一轮完整 current/history 对照要求 manifest 中已有足够的有效组标签。检查失败时明确报告缺多少组和独立照片，不用复制图片凑数。

### 8.5 默认查询采样

每个有效步骤默认最多三个查询：

- current/general 两个：一个优先取本步有实际观察的候选及对应外观组；另一个从本 episode 查询池均匀取车辆。
- history 一个：在此前已见的其他外观组中均匀取；没有合法历史查询则该位置关闭。
- 候选车辆索引在 episode 开始时随机排列，并在整个序列中保持一致；查询标签同步映射。
- 查询车辆尚未获得固定前端允许的观察，或根本不在候选集合中时，监督为 Null。
- 不凭空制造外部车辆查询；只有两车的数据可能缺少真正的外部负例，必须报告此限制。
- 不把低可见图一律排除出所有评估；可分“可辨查询”和“困难查询”报告，并说明筛选依据。

所有选择在模型训练前由固定 seed 生成 manifest，不能由模型当前对错挑选容易样本。均匀采样不是基于成绩挑选难例。

## 9. 可靠性训练与扰动

第一轮通过数据和任务损失学习鲁棒性，不新增可靠性头。默认试验配置是起始约定，不是已验证最优值：

- 70% 的实际可写观察保持原样。
- 15% 使用模糊版本：裁图缩放到约 256 像素尺度后进行 Gaussian blur，sigma 从 1 或 2 中固定采样，再按原约定编码。
- 15% 使用部分覆盖版本：覆盖约 15% 或 30% 的框内面积，保存位置和比例。
- 完全重复单独作为反事实分支，不通过额外时间步混入正常路线。
- 裁框偏移作为扩展压力集：移动框宽／高的 10%，保持框尺寸、裁到图像边界，记录真实裁后区域；第一轮不与上述训练分布同时叠加。

扰动先作用于 RGB，再由冻结编码器处理。对缓存 token 随意加噪声不能冒充图像模糊。写入扰动与原图共享 parent_sample_id，查询中排除全部同源版本。

上述比例适用于实际可写条目，不适用于所有时间步。一个多车帧的各车可独立采样，但所有方法复用相同扰动清单。

扰动名称不直接决定“应该拒收”。主要监督仍为真实身份查询；保留局部关键细节的样本应允许贡献信息。低质量观察导致什么变化通过配对评估判断。

不能把信息不足的第一帧与已有丰富记忆时的坏帧混成一类：分别报告 first_write 与 subsequent_write。

## 10. 标签与状态：三个概念不要混用

| 概念 | 含义 |
| --- | --- |
| physical_seen | 目标此前是否在图像中物理出现 |
| eligible_seen | 目标此前是否获得固定前端规则允许的观察 |
| has_memory / 实际 seen | 模型是否真正建立了该候选状态 |

本轮不增加学习拒写，正常路径中 eligible_seen 与建立状态基本对应；重复去重不会抹掉已建立状态。

新增查询的分类标签按固定 eligible_seen 和查询身份生成，不按本次模型预测、置信度或是否答 Null 改写。physical_seen 另作前端完整链路统计。对于没有可靠物理可见标签的其他数据源，不伪造该项指标。

后续如果加入学习拒写，必须先重新定义候选注册与可评分状态，不能继续用“未写入就永远 mask 掉且改标 Null”的方式获得虚假提升。本轮不提前实现这个扩展。

## 11. 损失函数的确定版本

### 11.1 独立查询识别

L_current 对 current/general 查询计算交叉熵。它监督更新后的记忆可用，但不直接等于“本步收益”。

L_history 对 history 查询计算同样的交叉熵，检查此前外观是否还能识别。它不要求保持旧模型的错误预测。

每组先在合法查询上平均，再在合法时间步、episode 上平均，避免长路线和查询较多的组无意获得更大权重。无合法条目的一组贡献 0，并记录分母；不能产生 NaN。

对 Null 与已有目标两类使用训练 manifest 统计的逆频率权重，总体均值归一到 1；不按固定身份 A/B 学不同类别权重。不存在某类时只计算存在类别并报告。权重写进 run.json，验证／probe 不参与计算。

### 11.2 完全重复稳定性

在一次正常更新之后，从正常状态 M_after 分出副本，只对本步选定的一辆车额外写入相同 observation 和 valid，得到 M_repeat。

    p_after  = softmax(score(M_after, Q))
    p_repeat = softmax(score(M_repeat, Q))
    L_repeat = KL(stop_gradient(p_after) || p_repeat)

- 使用相同查询、相同候选和 Null，温度固定为 1。
- 第一版每步至多选择一辆本步实际写入且此前已经有状态的车；训练默认每个 eligible step 以 0.25 概率启用。
- 额外写入绕过入口去重，否则测试不到更新器。
- 重复分支不成为下一正常时间步的状态。
- 只对正常状态已经正确识别、且标签为非 Null 的查询施加保持项；正确标志停止梯度。没有合格查询则该项为 0。
- 另行报告所有查询的重复变化，防止训练筛选掩盖错误。
- 重复正则必须与身份监督共存，否则“永远不更新”也能使它很小。
- 近似重复不套用严格不变约束，单独评价质量改善。

stop_gradient 只切断作为参照的概率分布；正常序列记忆仍保留完整 BPTT。重复分支通过自身计算路径训练更新器，不把它的状态写回主路径。

### 11.3 总损失和初始系数

    L = L_current + lambda_history * L_history + lambda_repeat * L_repeat

第一轮默认 lambda_history=1.0，lambda_repeat=0.1。必须同时报告各原始项、加权项和有效计数。这些值仅为预先固定起点，不在 probe 上搜索。

没有历史查询时，不假装 L_history 已得到监督。没有足够重复有效样本时，也不能声称完成重复稳定性训练。

## 12. 训练流程与参数控制

    冻结编码器；加载已校验特征
    为一个批次初始化车辆状态
    optimizer.zero_grad()
    对 t = 1 ... T：
        根据实际 valid 更新本步车辆；缺席车辆保持原状态
        用独立 current/general 查询读取当前记忆
        用独立 history 查询读取当前记忆
        若满足条件，在副本上额外重复写入，计算稳定性
        累计损失，主状态只接正常更新
    按约定分母归一化总损失
    total_loss.backward()
    clip_grad_norm_(参数, 1.0)
    optimizer.step()
    下一批次重新初始化车辆状态

- 第一轮保留完整短序列梯度，不在主序列中 detach。
- 不在序列中途 optimizer.step。
- 编码器参数被冻结，不包含在优化器；输出特征已缓存。
- Writer、Updater、Gate、Reader、Matcher 共同训练。因此整体改善不能自动归因为 Updater 独自学得更好。
- 第一轮先从相同公共参数初值训练，避免混用旧 Last 与新 Memory 的不同初始化。
- 学习率 1e-4，AdamW，weight_decay=0.01，batch_size=4，heads=4，slots=8，种子 7/17/27。
- 短试验使用 seed=7、4/8 步 episode 和最多 200 次优化更新；正式机制对照固定 2300 次更新，固定最终检查点。
- 训练预算、episode 清单和查询／扰动 seed 共享；不同损失的额外前向开销单独计时，不声称 FLOPs 相等。
- 若未来尝试截断 BPTT、共享冻结 Reader 或独立可靠锚点，作为单独实验，不在主线中静默改变。

## 13. 实验矩阵

| 编号 | 更新方式 | 训练项 | 回答的问题 |
| --- | --- | --- | --- |
| A | Last | current + history | 最近一次有效观察，在新任务下能做到多好 |
| B | Mean | current + history | 固定平均是否足够 |
| C | Memory | current | 独立当前／通用查询本身的效果 |
| D | Memory | current + history | 明确复习历史外观是否有帮助 |
| E | Memory | current + history + repeat | 重复稳定性是否带来额外收益 |

A、B、D 是同查询任务的主要存储策略对照；C→D→E 是训练目标消融。不要把 C 的少监督与 A 的全监督直接当成纯结构比较。

旧九组实验只作历史背景；新矩阵必须重新训练或严格标明为固定检查点迁移，不能混合成同条件表格。

先跑一个种子的短试验，确认工程和指标，再按固定协议跑三个种子。短试验只验证可训练与数据合理，不据此挑选最有利种子或改测试集。

## 14. 更新收益的配对评估

### 14.1 必须只改变一辆车的写入

旧 pause_current_write 会暂停本步所有车辆的写入，不能直接作为“某辆车此次更新的收益”。

新评估对本步实际写入的候选 i：

    S_before = 正常历史状态
    S_full   = 所有车辆执行本步正常更新
    S_skip_i = 从 S_before 出发，只关闭 i 的本步 valid，其余车仍正常更新

两条分支都读取相同的查询。正常路线下一步只使用 S_full。

主收益统计要求 i 在本步之前已有状态。这样两条分支的候选可用性一致，避免将“新增候选”误当成“改善旧记忆”。首次写入另报。

### 14.2 必须保存的指标

- help_rate：跳过 i 时错、正常更新后对，占全部合格配对的比例。
- harm_rate：跳过 i 时对、正常更新后错，占全部合格配对的比例。
- conditional_harm：上述有害次数 / 跳过 i 时原本正确的次数。
- net_gain：配对准确率差，也等于 help_rate - harm_rate。
- 两车／多车排序：只在至少两辆候选可用时统计，单独排除 Null 影响。
- Null 误拒绝率、目标不存在时的误接受率；当前数据若没有对应样本则标 N/A。
- margin_delta：同检查点内，正确车与最强错误车的概率差在更新前后如何变化。车间概率在可用车辆上重新归一化，另报 Null 概率变化。
- repeat_flip_rate：额外写同图 1/8 次后身份选择变化的比例，并分正常原本正确／错误。
- history_query_accuracy：历史外观独立查询正确率。
- query_accuracy：所有有效查询正确率及分子分母。
- per_vehicle、per_view_group、per_quality、first/subsequent_write 分层结果。

原始 logit 差可以保存作诊断，但不能跨独立训练模型当成同尺度的绝对信息量。概率或熵改善也不能代替真实身份正确性。

### 14.3 解释规则

可靠互补图应在总体上更常带来帮助；重复图应相对稳定；受损图应降低有害更新率。不能要求每个样本都符合趋势。

不能把编码器不含的细节当成更新器能够恢复的真值。若所有独立查询方法都无法分车，应先排查特征与数据。

按车辆／布局等独立单位汇总，另报三个种子的均值和离散程度。当前两车单场景仅供机制排查，不做有力的泛化显著性声明。

## 17. 验收条件

### 17.1 本机可做的检查

- 纯数据模块不导入 torch。
- 写入与查询的源图、增强父样本、裁图哈希交集检查通过。
- 跨外层划分身份与图像隔离按协议成立；smoke 的例外明确记录。
- 查询更换不改变写入路线、区域和状态构造清单。
- padding、空历史、无合法查询、候选顺序变化都不改错标签。
- 纯人工分数例子中 help/harm 和分母正确。
- 来源缺失、缓存角色错误、无有效 view_group 时明确报错或进入明确标记的 query_all 模式。

### 17.2 只在授权服务器执行的检查

- 独立查询为 64×256、写入为 16×256，编码器无梯度且不进入优化器。
- 正常序列梯度能到达较早时间步和 Updater；没有中途 detach。
- 不写入的车辆 slots、seen、count 原样保留。
- 不同查询只改变输出，不改变同一历史的状态。
- 候选排列保持等价；更改未来输入不改变此前输出。
- repeat / skip_i 从副本开始，不能污染后续正常轨迹。
- skip_i 保持其他车辆本步更新，首次写入不混入旧记忆收益。
- L_repeat 的参照概率停止梯度，重复分支确实执行 Updater。
- 无有效 history/repeat 时损失为有限的零，计数为零。
- 保存并加载检查点后，固定输入的最大得分误差不超过 2e-5。
- 重复训练数据表和公共初值哈希在相应对照间一致。

### 17.3 科学结果的通过与失败

工程通过不等于融合有效。正式报告必须允许“E 没有超过 A”“保持改善但吸收新证据变差”等结果。

只有在独立查询上、同条件对照下观察到收益，并且不是单靠拒绝所有更新或扩大容量取得，才能说本轮支持改进。新车泛化需要独立车辆测试；当前 smoke 无法完成这条验收。

## 19. 后续可选实验及进入条件

### 19.1 离线多视角融合

同样冻结输入编码器，联合读取历史，输出固定容量表示，在同一批独立查询上评价。它是经验参考，不是理论性能上限。

若加入顺序无关目标，网络不能使用时间序号编码，并应单独验证输入置换后的输出判断；写成集合符号本身不保证实现顺序不变。

### 19.2 Teacher–Student

只有离线融合器在开发集上稳定提供有效指导，再尝试行为蒸馏。教师冻结，第 t 步仅使用相同的历史前缀；查询不写入。保持真实身份损失，避免学生继承教师错误。优先对齐同候选下的判断分布，不强制独立训练的 token 逐元素相等。

### 19.3 多原型、可靠参照与选择性写入

质量／重复／互补训练已在第一阶段考虑；这里推迟的是结构改造。新增跳过、替换、分组局部更新或可靠参照时，分别报告容量、参数和读写计算量。

4 组×2 token 与现有 8 token 虽然总容量相同，却同时改变单次观察压缩程度，必须加入相应压缩对照。4 组×8 token 则明确是四倍状态容量，不能全归因于组织方式。

### 19.4 动作推荐

本轮更新收益是在已得到观察后计算的，不能直接用于飞到尚未观察的位置。动作推荐还需要候选动作的预测、价值估计和闭环评估，另立设计，不把事后收益冒充事前规划能力。
